# Supabase 云同步配置

1. 在 https://supabase.com 创建项目，在 SQL Editor 执行 [supabase.sql](supabase.sql)。该脚本可重复执行。
2. 在 Authentication 开启 Email 登录。保留邮件确认时，注册后先确认邮件再登录。
   - 在 **Authentication → URL Configuration → Site URL** 将默认的 `http://localhost:3000` 改为可访问的 HTTPS 网页，例如 `https://github.com/linianchen666/wordpop`，保存。该页面仅作邮件确认后的落地页，确认后手动回到 WordPop 登录，无需在网页填写账户信息。
   - 如果旧邮件最终跳到了 localhost 并打不开，先回软件尝试登录，邮箱可能已确认。若仍未确认，修改 Site URL 后点击应用的“重发确认邮件”，使用最新链接。不要分享包含验证信息的完整邮件链接。
   - Supabase 默认邮件服务限制收件人和发送额度；供其他用户注册前，在 Authentication 的 Email/SMTP 设置配置自己的邮件服务。应用会显示未确认、邮件限流、收件人不受支持等具体提示。
3. 在项目 API 设置找到项目 URL 和公开的 publishable key（旧项目可用 anon key）。不要把 service_role 或 secret key 填入应用。
4. 电脑端和安卓端已预填默认项目 URL 和公开密钥，使用默认项目时只需填写邮箱和密码。使用自建项目时可展开“高级连接设置”修改这两个字段；默认项目更换地址或轮换公开密钥后，需要更新应用默认值或手动修改。
5. 先使用包含云同步功能的电脑版本：设置 → 电脑与手机云同步，注册或登录。电脑当前记录作为初始进度上传。
6. 安卓安装 APK，在云同步设置中用同一项目和账户登录。

## 记忆记录如何同步

以下为当前 main 源码的同步方式，安装包需要在下一次发布后获得这些改进。

- 评分先提交到本地 SQLite，卡片切换无需等待云请求。评分、撤销各有唯一 ID；仅上传未确认的操作，网络失败或回执丢失时保留记录并重试，重复上传不会重复计数。
- 评分后约 750 毫秒发起后台同步，短时间的操作合并到一次请求；同步期间新增的评分在当前请求完成后自动续传。显示释义、查看卡片、改变小组件尺寸或学习设置不触发评分上传。
- 电脑和已打开的手机每 5 秒检查另一端的新记录。首次登录和手机回到前台时也检查；无新记录时跳过进度重写、队列重置和小组件更新，初始快照在进程内缓存。拉取目前仍分页读取完整事件日志，不使用评分时间作为增量游标，以免漏掉离线设备补传的较早评分。
- 手机评分同时登记有网络约束的一次性 WorkManager 补传任务：即时同步未完成、退出 App 或恢复联网时由系统继续处理；已上传完则直接结束。另保留最短 15 分钟的周期检查，用于接收电脑的新记录。待机、节电或系统调度可能使后台任务延迟，不保证息屏时实时刷新，也不依赖 Google 推送服务。
- 同步状态区分“正在同步”“已同步”和“已保存本地、等待上传/重试”。电脑退出云账户会阻止正在拉取的请求继续应用记录，本地已保存的记录保留。

本次改进复用原有云表和事件，不清空旧记录，不需要重新执行 SQL。

评分事件使用唯一 ID，重复上传不会重复评分；按评分时间及 ID 排序重算 FSRS，两个设备同时评分时保留双方事件。设备时间早于已有记录时以已有记录时间计算记忆，原评分时间仍保留。Windows 撤销作为撤销事件同步；电脑也保存云端撤销标记及暂未安装词库的评分，安装对应词库后可恢复其进度。初始云快照和事件归登录账户所有，RLS 隔离不同用户。

手机首次连接时采用电脑初始快照中的学习设置；之后两端设置分别选择，同步的是学习记录和评分；手机词库为内置四级、六级、考研。当前卡片、是否展开释义、窗口/小组件外观、新词计划和选中词库均为设备本地状态；两端待复习和待新学数量因此不保证相同。电脑的逾期平摊只调整本地队列，不制造评分、不同步为手机的复习日期；同步其他单词时保留平摊安排，该单词有新评分后以新的 FSRS 时间为准。账号连接后不要在电脑直接导入另一份备份覆盖本地记录；请先退出云同步，并为不同学习账户使用独立本地配置。服务器建表及真实账户连接需要使用者完成；本地模拟接口验证不等于已在你的 Supabase 项目验证。
