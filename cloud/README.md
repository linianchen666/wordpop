# Supabase 云同步配置

1. 在 https://supabase.com 创建项目，在 SQL Editor 执行 [supabase.sql](supabase.sql)。该脚本可重复执行。
2. 在 Authentication 开启 Email 登录。保留邮件确认时，注册后先确认邮件再登录。
   - 在 **Authentication → URL Configuration → Site URL** 将默认的 `http://localhost:3000` 改为可访问的 HTTPS 网页，例如 `https://github.com/linianchen666/wordpop`，保存。该页面仅作邮件确认后的落地页，确认后手动回到 WordPop 登录，无需在网页填写账户信息。
   - 如果旧邮件最终跳到了 localhost 并打不开，先回软件尝试登录，邮箱可能已确认。若仍未确认，修改 Site URL 后点击应用的“重发确认邮件”，使用最新链接。不要分享包含验证信息的完整邮件链接。
   - Supabase 默认邮件服务限制收件人和发送额度；供其他用户注册前，在 Authentication 的 Email/SMTP 设置配置自己的邮件服务。应用会显示未确认、邮件限流、收件人不受支持等具体提示。
3. 在项目 API 设置找到项目 URL 和公开的 publishable key（旧项目可用 anon key）。不要把 service_role 或 secret key 填入应用。
4. 电脑端和安卓端已预填默认项目 URL 和公开密钥，使用默认项目时只需填写邮箱和密码。使用自建项目时可展开“高级连接设置”修改这两个字段；默认项目更换地址或轮换公开密钥后，需要更新应用默认值或手动修改。
5. 先使用包含云同步功能的电脑版本：设置 → 电脑与手机云同步，注册或登录。电脑当前记录作为初始进度上传。
6. 安卓安装 APK，在云同步设置中用同一项目和账户登录。

## 安卓同步 400 排查

Android 0.1.7 已修复批量上传的格式问题：普通评分、撤销、离线重试统一使用 `id,user_id,word,action,reviewed_at,target_id` 六个字段，普通评分显式发送 `target_id: null`，不上传服务器生成的 `created_at`。此前评分和撤销混合时可能触发 PostgREST 的“对象字段必须一致”错误，导致整批上传返回 400。修复不修改已有事件、同步确认或下载缓存，也不需要改表；失败的本地记录继续等待重试。

新错误提示区分读取初始记录、上传评分、检查数量及下载评分，并显示 HTTP 状态和安全的服务错误码。`PGRST102` 表示请求体格式有误；`PGRST204` / `42703` 表示字段不完整，`PGRST205` / `42P01` 表示表不可用，`23514` 表示校验约束不兼容，这些云表问题应核对并执行最新建表脚本；`42501` 需核对权限及 RLS。旧版只显示“400”，仅凭该提示不能断定具体失败步骤或原因。

失败时保留本地学习记录，修复后可继续补传；排查时避免卸载应用或清除应用数据。

## 记忆记录如何同步

Android 0.1.5 / Windows 1.9.1 正式版提供批量上传、数量检查和增量下载，安装包位于 [v1.9.1 发布页](https://github.com/linianchen666/wordpop/releases/tag/v1.9.1)。

- 评分先提交到本地 SQLite，卡片切换无需等待云请求。评分、撤销各有唯一 ID；仅上传未确认的操作，网络失败或回执丢失时保留记录并重试，重复上传不会重复计数。
- 评分后启动 10 秒固定窗口，将期间的操作合并到一次上传，连续评分不延长截止时间；同步期间新增评分进入下一批。手机离开 App 时尝试提前补传，手动“立即同步”会取消等待并完整检查。显示释义、查看卡片、改变小组件尺寸或学习设置不触发评分上传。
- 电脑和已打开的手机每 15 秒检查另一端的新记录，不提前打断待上传的批次。首次登录和手机回到前台时也检查；使用 Supabase 的 `count=exact` 和 `limit=0` 查询当前账户事件总数，数量未变则不下载日志、不重写进度、不重置队列。
- **只下载新增评分**：按服务器已有的 `created_at` 和事件 UUID 组合做游标分页，保留微秒精度；不按设备答题时间筛选，离线补传的旧评分也能下载。评分与撤销走同一条增量链路；在本地合并完整历史重新计算记忆，不会仅用新增评分覆盖旧进度。下载缓存按项目地址和账户隔离，保存在本地 SQLite，重启及手机后台进程重建后继续增量。
- **完整校验**：首次登录、没有有效缓存、手动“立即同步”、距离上次完整校验达到 24 小时、记录数量减少或增量核对发现缺口时，从头分页读取。服务器 `created_at` 是事务开始时间，不保证按提交顺序增加；若某事务延迟提交到游标之前，最终精确总数会揭示缺口，自动完整补齐。下载途中出现尾部新记录时，继续增量补取，不因此重读历史；尾部取完仍有数量缺口才完整重试。连续新增暂时追不上时保留旧缓存，下一次继续。数量响应不可用时退回完整读取并停用该次增量缓存。分页失败或本地合并失败不保存新缓存，因此重试不会跳过记录。
- 初始云快照仍在进程内缓存；客户端按云表的只追加约定工作，普通账户不能修改或删除事件，撤销也追加为新事件。不要在服务端手动改写/删除已同步的事件。
- 手机评分同时登记有网络约束的一次性 WorkManager 补传任务：即时同步未完成、退出 App 或恢复联网时由系统继续处理；已上传完则直接结束。另保留最短 15 分钟的周期检查，用于接收电脑的新记录。待机、节电或系统调度可能使后台任务延迟，不保证息屏时实时刷新，也不依赖 Google 推送服务。
- 同步状态区分“正在同步”“已同步”和“已保存本地、等待上传/重试”。电脑退出云账户会阻止正在拉取的请求继续应用记录，本地已保存的记录保留。

本次改进复用原有云表、`created_at` 字段和事件，不清空旧记录，不需要重新执行 SQL。Android 首次启动只升级本地数据库以保存下载缓存，原学习记录保留。

评分事件使用唯一 ID，重复上传不会重复评分；按评分时间及 ID 排序重算 FSRS，两个设备同时评分时保留双方事件。设备时间早于已有记录时以已有记录时间计算记忆，原评分时间仍保留。Windows 与 Android 的撤销作为指向原评分 ID 的撤销事件同步；电脑也保存云端撤销标记及暂未安装词库的评分，安装对应词库后可恢复其进度。初始云快照和事件归登录账户所有，RLS 隔离不同用户。

手机首次连接时采用电脑初始快照中的学习设置；之后两端设置分别选择，同步的是学习记录和评分；手机词库为内置四级、六级、考研。当前卡片、是否展开释义、窗口/小组件外观、新词计划和选中词库均为设备本地状态；两端待复习和待新学数量因此不保证相同。电脑的逾期平摊只调整本地队列，不制造评分、不同步为手机的复习日期；同步其他单词时保留平摊安排，该单词有新评分后以新的 FSRS 时间为准。账号连接后不要在电脑直接导入另一份备份覆盖本地记录；请先退出云同步，并为不同学习账户使用独立本地配置。服务器建表及真实账户连接需要使用者完成；本地模拟接口验证不等于已在你的 Supabase 项目验证。
